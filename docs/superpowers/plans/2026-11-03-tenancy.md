# Tenancy (Phase 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tenant-saas` projects get stancl/tenancy set up by `engineering:install`, a retry-safe `tenant:create`, domain-separated tenant/central module routes, tenant-aware `make:module`/`make:crud`, a testing helper, and isolation tests.

**Architecture:** Small support classes hold every decision: `TenancyDetector` (stancl present + profile), `TenantDomains` (central domains, base domain, validation), `TenancySetup` (idempotent install steps), `TenantSetup` (idempotent tenant steps 4–8, shared by `tenant:create` and the testing helper). The package registers the `tenant`/`central` middleware groups and middleware priority itself. Generators pick tenant/central stubs from the profile and the module's Provider.

**Tech Stack:** PHP 8.3, Laravel 12 + 13, stancl/tenancy ^3.10, Testbench ^10 || ^11, Pest 4.

**Spec:** `docs/superpowers/specs/2026-11-03-tenancy-design.md`

## Global Constraints

- No tenancy class referenced unless `class_exists` guards it; the package must load without stancl (`composer.json`: `require-dev` + `suggest` `stancl/tenancy: ^3.10`).
- Non-`tenant-saas` behavior and all Phase 1–5 tests unchanged.
- Messages and step lines exactly as spec §4–§5.
- Package tests: Testbench, central DB sqlite in a temp file, tenant DBs via stancl's SQLite manager; register `Stancl\Tenancy\TenancyServiceProvider` in tenancy test cases only.
- Done = `vendor/bin/pest` green on Laravel 13 and 12, output shown.

## Generated providers (decided shape)

Tenant module (`make:module Orders --api --web`, `tenant-saas`):

```php
<?php

declare(strict_types=1);

namespace App\Modules\Orders;

use Illuminate\Support\Facades\Route;
use Illuminate\Support\ServiceProvider;

final class Provider extends ServiceProvider
{
    public function boot(): void
    {
        if ($this->app->routesAreCached()) {
            return;
        }

        // Registered after central routes, so central (domain-bound) routes win on central hosts.
        $this->app->booted(function (): void {
            Route::middleware(['web', 'tenant'])->group(__DIR__.'/routes/web.php');
            Route::middleware(['api', 'tenant'])->prefix('api')->group(__DIR__.'/routes/api.php');
        });
    }
}
```

Central module (`make:module Admin --api --central`): `boot()` body after the cache check:

```php
        $domains = implode('|', array_map('preg_quote', config('tenancy.central_domains', [])));

        Route::domain('{central_domain}')->where(['central_domain' => $domains])->middleware(['web', 'central'])->group(__DIR__.'/routes/web.php');
        Route::domain('{central_domain}')->where(['central_domain' => $domains])->middleware(['api', 'central'])->prefix('api')->group(__DIR__.'/routes/api.php');
```

(only the lines for route files that exist, as in Phase 3).

## Review Focus

1. Shared URI (`/api/orders`) in a central and a tenant module — each host gets its own controller. → Task 7 `same uri resolves per host`.
2. Central-domain request to a tenant route with a model-bound URL — 404, not 500 (middleware priority). → Task 2 `central host gets 404 before binding`.
3. `tenant:create` retry after a failed tenant migration in the same process — tenancy ended, resume works. → Task 4 `retries after failure`.
4. `APP_URL` with a port (`http://localhost:8000`) — central domain is `localhost`, tenant URLs keep the port. → Task 1 `ignores port in APP_URL`.
5. Package installed without stancl — every command and provider boots; `make:module` in `tenant-saas` without stancl refuses with the composer hint. → Task 1/6.
