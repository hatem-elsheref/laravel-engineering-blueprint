Tenancy

The tenant-saas profile gives each tenant its own subdomain and its own database, using stancl/tenancy ^3.10. The central database only keeps the tenant and domain registry.

Set up

$ composer require stancl/tenancy:^3.10
$ php artisan engineering:install --profile=tenant-saas
$ php artisan migrate
$ php artisan tenant:create acme

The install step runs tenancy:install once, creates app/Models/Tenant.php, sets tenant_model and central_domains in config/tenancy.php (the APP_URL host, localhost and 127.0.0.1), copies the users migration to database/migrations/tenant/ and registers App\Providers\TenancyServiceProvider. Every step can run again safely.

Tenants are <name>.<base>. Set the base domain with BLUEPRINT_TENANT_DOMAIN (config blueprint.tenant_domain). When it is empty, the first central domain that is not an IP address is used, or localhost.

make:crud in a tenant module writes its migration to database/migrations/tenant/; in a central module, to database/migrations/. Do not put migration folders inside modules.

Create a tenant

$ php artisan tenant:create acme --domain=acme.example.com --database=tenant_acme

tenant:create acme

Defaults: domain acme.<base>, database tenant_acme (dashes in the name become underscores). The command validates the name and domain, checks for duplicates, then creates the tenant record, the domain record and the database, runs tenant migrations, seeds, and inserts the default features.

  • Generated A tenant ready at its domain, with each step printed as done, already done or skipped.
  • Refused the central database, another tenant's database, a domain owned by another tenant, a domain outside the base domain, and an existing database unless --existing-database is passed.
  • Note Safe to retry. After a failure, fix the cause and run the same command; finished steps are skipped.

See also: tenant:create options

  • Names use lowercase letters, numbers and dashes.
  • Seeding runs blueprint.tenant_seeder (default Database\Seeders\TenantSeeder) when that class exists, otherwise the step is skipped.
  • Default features come from Features::defaults(). Settings need no rows: their defaults come from the definitions.
  • Run it from the central app. Do not create tenants through a tenant-facing endpoint.

Route groups

ModuleCreated withMiddleware groupAnswers on
Tenant modulemake:module Orderstenant: InitializeTenancyByDomain and PreventAccessFromCentralDomainsTenant domains
Central (platform) modulemake:module Plans --centralcentralCentral domains only
  • Unknown tenant domains return 404.
  • Tenant module routes are registered after central routes, so central routes win on central hosts.
  • Your app's own routes/web.php and routes/api.php answer on every domain and win over tenant routes with the same URI. Wrap central-only routes in Route::domain(...) or move them into a --central module.

Central modules

$ php artisan make:module Plans --api --web --central
$ php artisan make:crud Plans Plan --api --web --fields="name:string,price:float"

A central module is for the platform itself, such as plans or billing. Its routes answer only on tenancy.central_domains, its route names start with central. (central.plans.index, central.api.plans.index) and its tables live in the central database. make:crud --feature is refused here, because features are per tenant.

Sessions, queue, cache

AreaBehaviour
SessionsA web session belongs to the tenant (or the central app) where it started. The same cookie on another tenant or on the central domain gets 403, whatever the session driver.
QueueThe database queue connection is pinned to the central connection (unless you set one), so workers find jobs dispatched inside a tenant.
CacheTenant cache isolation needs a store with tags. Set CACHE_STORE=redis (or memcached); the database and file stores fail inside tenants. The install command warns when the store has no tags.
SchedulerRun tenant work with php artisan tenants:run <command>.

Testing

Use Best\Blueprint\Testing\InteractsWithTenancy in tests: createTestTenant() creates a real test tenant and tenantUrl('/orders') builds a URL on its domain. The tests make:crud generates for tenant modules already use it.
