Commands

The package registers 13 Artisan commands. Every refusal prints one error line and exits with status 1; generators write nothing when they refuse.

CommandDescription
engineering:aboutShow Laravel Engineering Blueprint version and environment compatibility
engineering:installSet up this app with a Laravel Engineering Blueprint project profile
make:moduleCreate a business module in app/Modules and register its provider
make:dtoCreate a Data class (typed, immutable) in a module
make:actionCreate an Action (one business operation) in a module
make:crudCreate a CRUD for an entity in a module: JSON API (--api), Blade pages (--web) or both
make:nested-crudNested JSON API CRUD under a parent entity (see docs/NESTED-RESOURCES.md)
tenant:createCreate a tenant: records, domain, database, migrations and seed data (safe to re-run)

engineering:about

$ php artisan engineering:about

No arguments or options. Prints the package version, the recorded profile (or not installed (run php artisan engineering:install)) and a PHP and Laravel check against blueprint.support.

  • Refused Exit 1 with Environment is not compatible: upgrade the items marked ✗.

engineering:architecture

$ php artisan engineering:architecture [--path=PATH]

Scans module PHP files for cross-module imports that break MODULE-BOUNDARIES.md (for example another module’s Models or Controllers). Allowed cross-module paths include public Actions, Queries, Events and Jobs.

  • Success Exit 0 — no violations (or no module directory).
  • Refused Exit 1 — violations listed; tune rules in blueprint.architecture.

engineering:install

$ php artisan engineering:install [--profile=PROFILE] [--force] [--allow-downgrade] [--permissions]
OptionMeaningDefault
--profile=basic, modular, saas or tenant-saasAsked interactively. Non-interactive: the recorded profile, else blueprint.default_profile, else modular
--forceOverwrite the published config file (old one kept as config/blueprint.php.bak); also allows a downgradeoff
--allow-downgradeAllow switching to a profile with fewer capabilitiesoff
--permissionsSet up roles and permissions: creates the Permissions definitions class (and CentralPermissions in tenant-saas), spatie's migration (also in database/migrations/tenant in tenant-saas) and adds HasRoles to App\Models\User. Refused without spatie/laravel-permission 8 or later, and in spatie's teams mode; safe to re-run. Then run php artisan migrate; a tenant-saas app with existing tenants also runs php artisan tenants:migrate, permissions:sync and permissions:sync --centraloff

Records the profile in config/blueprint.php (publishes it when missing), clears a cached config, and in saas/tenant-saas generates the feature and setting definitions and migrations; in tenant-saas it also sets up stancl/tenancy.

  • Refused Install aborted: environment is not compatible.
  • Refused Unknown profile "<value>". Choose one of: basic, modular, saas, tenant-saas.
  • Refused Non-interactive downgrade: Refusing to drop <capabilities>. Re-run with --allow-downgrade. Interactive: asks This removes <capabilities> from the project. Continue? (default no).
  • Refused Could not record the profile in config/blueprint.php.

make:module

$ php artisan make:module <name> [--api] [--web] [--central]
Argument / optionMeaningDefault
nameModule name, e.g. Ordersrequired
--apiAdd routes/api.php (loaded with the api group and the /api prefix)off

--centraltenant-saas only: a platform module whose routes answer on central domainsoff (tenant module)

Writes <module_path>/<Name>/Provider.php and the chosen route files, and registers the provider in bootstrap/providers.php.

  • Refused No project profile installed. Run php artisan engineering:install first.
  • Refused The "basic" profile has no modules. Switch profile with php artisan engineering:install --profile=modular.
  • Refused module_path must be inside app/ (got "<value>").
  • Refused --central only applies to the tenant-saas profile.
  • Refused Invalid module name "<name>". Use letters and numbers, starting with a letter, e.g. Orders.
  • Refused "<module_path>/<Name>" already exists. Nothing was changed.

make:crud

$ php artisan make:crud <module> <entity> [--fields=LIST] [--schema=PATH] [--feature=KEY] [--api] [--web] [--permissions] [--owned]
Argument / optionMeaningDefault
moduleModule name, e.g. Ordersrequired
entitySingular entity name, e.g. Orderrequired
--fields=Comma-separated name:type list, e.g. "name:string,quantity:int,note:?string"none; when adding a side to an existing CRUD, the existing fields are reused
--schema=Entity YAML (enums, foreign keys, indexes, soft deletes); see package docs/SCHEMA-DSL.md. Do not combine with --fieldsnone
--feature=Feature key that must be enabled for these routes (saas, tenant-saas); adds feature:<key> middlewarenone (no gate)
--apiJSON APIon when neither --api nor --web is given
--webBlade pagesoff
--permissionsThe policy checks named permissions (<uri>.view, .create, .update, .delete); the group is added to Permissions::groups() (CentralPermissions for a central module) and the tests prove the rules. Needs engineering:install --permissionsoff
--ownedRecords belong to the user who creates them: a user_id column set by the create action (never from input), a list scoped to the user's records, and an extra <uri>.any permission that widens the permissions a user holds to every record. A record the user cannot view is 404. Needs --permissionsoff

Run again with the other side (--web after --api, or the reverse) to add it; the shared model, data, actions and policy are reused. The first --web run also creates the layout named by blueprint.layout.

  • Refused Invalid entity name "<entity>". Use a singular name, e.g. Order.
  • Refused Entity names must be singular, e.g. <singular>.
  • Refused --owned needs --permissions.
  • Refused --permissions needs spatie/laravel-permission. Run: composer require spatie/laravel-permission && php artisan engineering:install --permissions
  • Refused spatie/laravel-permission <version> is not supported; permissions need ^8.0. or spatie teams mode (permission.teams) is not supported.
  • Warning The '<group>' group in <file> has no '<ability>'; another CRUD may use it. Add '<ability>' to '<group>' in <file>, then … (the group was already defined without an ability this CRUD checks)
  • Refused --feature needs the saas or tenant-saas profile.
  • Refused Unknown feature "<key>". Add it to <FeaturesClass> first.
  • Refused Features are per tenant; central module routes have no tenant. Drop --feature or use a tenant module.
  • Refused The module has no routes/api.php or routes/web.php for the requested side.
  • Refused In tenant-saas, a module whose routes use neither the tenant nor the central group.
  • Refused An entity whose singular and plural are the same, with --web.
  • Refused Use --schema or --fields, not both. or Leave --schema out when adding a side; the existing fields are reused.
  • Refused --fields doesn't match the existing <Entity> CRUD (<fields>). Leave --fields out to reuse them.
  • Refused A target file already exists, a route name is already taken, the entity clashes with a class the generated code uses, or a stub produces invalid code.
  • Refused Adding a side with a different --feature than the existing side's routes.

See also: Route names · CRUD: Blade & API

make:nested-crud

$ php artisan make:nested-crud <module> <parent> <entity> [--fields=] [--schema=] [--permissions]

Same as make:crud … --api --nested-under=<parent>. Adds a parent foreign key and registers nested Route::apiResource.

tenant:create

$ php artisan tenant:create <name> [--domain=DOMAIN] [--database=NAME] [--existing-database]
Argument / optionMeaningDefault
nameTenant id, lowercase letters, numbers and dashesrequired
--domain=Full domain; must be a subdomain of the base domain<name>.<base domain> (base: blueprint.tenant_domain, else the first non-IP central domain, else localhost)
--database=Database name (letters, numbers, underscores)tenant_<name> with dashes turned into underscores
--existing-databaseUse a database that already exists for this new tenantoff

Creates the tenant record, domain, database, runs tenant migrations and seeds with blueprint.tenant_seeder when that class exists. Safe to re-run: finished steps are skipped.

  • Refused Without the tenant-saas profile and stancl/tenancy, or when App\Providers\TenancyServiceProvider is not registered.
  • Refused Run tenant:create from the central app, not inside a tenant.
  • Refused Invalid tenant name "<name>". Use lowercase letters, numbers and dashes, e.g. acme.
  • Refused Invalid domain "<domain>": it must be a subdomain of <base>.
  • Refused Domain "<domain>" already belongs to tenant "<id>".
  • Refused Database "<db>" is the central database.
  • Refused Database "<db>" already exists. Pass --existing-database to use it for this tenant.

Feature and setting commands. The seven commands below need the saas or tenant-saas profile. In saas they act on the app and --tenant is refused; in tenant-saas, --tenant is required (except for features:sync). Shared refusals:

  • Features and settings need the saas or tenant-saas profile.
  • --tenant only applies to the tenant-saas profile.
  • --tenant is required in the tenant-saas profile.
  • Tenant "<id>" not found.

features:sync

$ php artisan features:sync [--tenant=ID ...]
OptionMeaningDefault
--tenant=*Tenant ids (tenant-saas); repeatableall tenants when omitted

Adds a row in the default state for each defined feature that has none; existing rows are kept. In tenant-saas every requested tenant is checked before any is synced; a tenant that fails is reported and the command exits 1.

permissions:sync

$ php artisan permissions:sync [--prune] [--tenant=ID ...] [--central]
OptionMeaningDefault
--pruneDelete permissions and roles that are not in the definitionsoff; they are listed as stale, with a hint that names the side
--tenant=tenant-saas: sync Permissions into these tenants (repeatable)all tenants
--centraltenant-saas: sync CentralPermissions into the central database. Cannot be combined with --tenantoff

Creates missing permissions and roles from the definitions class (blueprint.permissions) and sets each defined role to exactly what the file says. The blueprint.super_admin role is created and passes every check; blueprint.permission_guard sets the guard. Entries not in the file are listed as stale and deleted only with --prune. A definition error exits 1 and writes nothing. blueprint.central_permissions is the central-side definitions class for tenant-saas. Tenant databases only ever receive Permissions and the central database only CentralPermissions; tenant:create syncs the new tenant. Patterns (products.*, *) are expanded at sync time and a pattern that matches nothing is an error. Run it from the central app. spatie's configured models and table names are used. See CRUD.

  • Refused Permissions need spatie/laravel-permission. Run: composer require spatie/laravel-permission
  • Refused spatie/laravel-permission <version> is not supported; permissions need ^8.0. or spatie teams mode (permission.teams) is not supported.
  • Exit 1 no permission tables — run php artisan migrate (single database, or central: with --central), or Tenant "<id>": no permission tables — run php artisan tenants:migrate (the other tenants are still synced)
  • Refused --tenant and --central only apply to the tenant-saas profile.
  • Refused Tenant "<id>" not found.

Publishing

TagCopiesTo
blueprint-configconfig/blueprint.phpconfig/blueprint.php

$ php artisan vendor:publish --tag=blueprint-config
$ php artisan vendor:publish --tag=blueprint-stubs

Stub lookup order: blueprint.stub_path, then stubs/blueprint/, then the package. A stub with an unknown placeholder, or one that no longer produces the expected class or route, is refused with Update or delete it, then re-run.
