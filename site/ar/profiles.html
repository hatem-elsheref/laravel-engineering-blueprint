الأنماط

النمط (profile) يحدد ما تجهّزه الحزمة في تطبيقك. هناك أربعة أنماط، كل واحد منها يضيف إلى الذي قبله: basic وmodular وsaas وtenant-saas.

مقارنة

النمطالوحداتالميزات والإعداداتتعدد المستأجرين
basicلالالا
modularنعم، في app/Modules/لالا
saasنعمنعم، مجموعة واحدة للتطبيق كله، في قاعدة بيانات التطبيقلا
tenant-saasنعمنعم، مجموعة لكل مستأجر، في قاعدة بيانات كل مستأجرstancl/tenancy ^3.10، قاعدة بيانات لكل مستأجر
  • basic: تطبيق Laravel عادي يتبع أعراف الحزمة. مولّدات الوحدات (make:module وmake:dto وmake:action وmake:crud) ترفض التنفيذ.
  • modular: كود الأعمال يعيش في وحدات داخل app/Modules/. هذا هو النمط الافتراضي.
  • saas: modular مضافًا إليه الميزات والإعدادات المخزّنة في قاعدة بيانات التطبيق.
  • tenant-saas: saas مضافًا إليه تعدد المستأجرين. الميزات والإعدادات تُخزَّن في قاعدة بيانات كل مستأجر.

تثبيت نمط

$ composer require best/laravel-engineering-blueprint
$ php artisan engineering:install --profile=saas

بدون --profile يسألك الأمر، ويقترح النمط المسجَّل مسبقًا أو blueprint.default_profile (modular). في طرفية غير تفاعلية يستخدم تلك القيمة الافتراضية.

engineering:install --profile=saas

يفحص إصدارَي PHP وLaravel أولًا، ثم يسجّل النمط ويجهّز ما يحتاجه. إعادة تشغيله آمنة: الخطوات المكتملة تطبع already set up.

  • أُنشئ config/blueprint.php مع 'profile' => 'saas' (يُنشأ الملف، أو يُحدَّث سطر النمط).
  • أُنشئ app/Shared/Features/Features.php وapp/Shared/Settings/Settings.php وترحيلا features وsettings (في saas وtenant-saas فقط).
  • مرفوض نمط غير معروف، أو بيئة غير متوافقة، أو انتقال إلى نمط بقدرات أقل بدون --allow-downgrade.

انظر أيضًا: خيارات engineering:install · engineering:about

ما يكتبه التثبيت

النمطالملفات والتغييرات
كل الأنماطconfig/blueprint.php مع تسجيل النمط. تُمسح الإعدادات المخزّنة مؤقتًا (config cache).
saas، tenant-saasأصناف تعريف الميزات والإعدادات في app/Shared/، وترحيلات لجدولَي features وsettings (في database/migrations/ لـ saas، وdatabase/migrations/tenant/ لـ tenant-saas).
tenant-saasيشغّل tenancy:install (مرة واحدة)، وينشئ مجموعة مسارات فارغة للمستأجر في routes/tenant.php، وapp/Models/Tenant.php، ويضبط tenant_model وcentral_domains في config/tenancy.php، وينسخ ترحيل المستخدمين إلى database/migrations/tenant/، ويسجّل App\Providers\TenancyServiceProvider. راجع تعدد المستأجرين.

ينتهي الأمر بطباعة الخطوة التالية للنمط، مثل php artisan migrate && php artisan features:sync لـ saas. افحص النمط المسجَّل والبيئة في أي وقت:

$ php artisan engineering:about

كيف تختار

إذا كان تطبيقكاستخدم
صغيرًا، أو تريد الأعراف فقطbasic
يضم عدة مجالات أعمال (طلبات، منتجات، مخزون)modular
يحتاج إلى تشغيل قدرات وإيقافها، أو إلى إعدادات محددة الأنواع، لقاعدة عملاء واحدةsaas
يخدم عملاء كثيرين، لكل منهم نطاقه الفرعي وقاعدة بياناتهtenant-saas

إن لم تكن متأكدًا، ابدأ بـ modular. الانتقال إلى نمط أعلى لاحقًا يحتفظ بوحداتك والكود المولّد.

الانتقال إلى نمط أعلى

شغّل أمر التثبيت مرة أخرى بالنمط الأكبر. تبقى الوحدات الموجودة والكود المولّد كما هي.

$ php artisan engineering:install --profile=saas
$ php artisan migrate
$ php artisan features:sync

لـ tenant-saas، ثبّت stancl/tenancy أولًا:

$ composer require stancl/tenancy:^3.10
$ php artisan engineering:install --profile=tenant-saas
$ php artisan migrate
$ php artisan tenant:create acme

وحدات أُنشئت قبل tenant-saas. مساراتها لا تستخدم مجموعة الوسائط tenant ولا central. أمر التثبيت يسردها، وmake:crud يرفضها حتى تضيف 'tenant' (بيانات لكل مستأجر) أو 'central' (المنصة) إلى استدعاءات Route::middleware(...) في ملف Provider.php الخاص بكل منها.

الانتقال إلى نمط أدنى

النمط ذو القدرات الأقل (مثلًا من saas إلى modular) يُسقط الميزات أو الإعدادات أو تعدد المستأجرين. في الطرفية التفاعلية يطلب الأمر تأكيدك، وإلا فإنه يرفض ما لم تمرّر --allow-downgrade:

$ php artisan engineering:install --profile=modular --allow-downgrade

ينبّهك إلى الوحدات التي يكسرها التغيير: الوحدات التي تستخدم مجموعتَي المسارات tenant أو central، والوحدات التي تستخدم مساراتها الوسيط feature:. لا يحذف أي ملفات.

--force يعيد كتابة config/blueprint.php من نسخة الحزمة ويحفظ الملف القديم باسم config/blueprint.php.bak. ويتخطى أيضًا فحص الانتقال إلى نمط أدنى.
