الأوامر

تسجّل الحزمة 13 أمرًا من أوامر Artisan. كل رفض يطبع سطر خطأ واحدًا وينتهي برمز الخروج 1، والمولّدات لا تكتب شيئًا عند الرفض.

الأمرالوصف
engineering:aboutيعرض إصدار Laravel Engineering Blueprint وتوافق البيئة
engineering:installيجهّز التطبيق بأحد أنماط Laravel Engineering Blueprint
make:moduleينشئ وحدة أعمال في app/Modules ويسجّل مزوّد الخدمة الخاص بها
make:dtoينشئ صنف بيانات (محدد الأنواع، غير قابل للتغيير) في وحدة
make:actionينشئ إجراء (عملية أعمال واحدة) في وحدة
make:crudينشئ CRUD لكيان في وحدة: JSON API (--api)، أو صفحات Blade (--web)، أو كليهما
tenant:createينشئ مستأجرًا: السجلات، والنطاق، وقاعدة البيانات، والترحيلات، والبيانات الأولية (إعادة تشغيله آمنة)
feature:listيسرد الميزات وحالتها (مدير المنصة)
feature:enableيفعّل ميزة (مدير المنصة)
feature:disableيعطّل ميزة (مدير المنصة)
features:syncيضيف الميزات المعرّفة حديثًا (بحالتها الافتراضية) دون تغيير الموجودة
permissions:syncينشئ الصلاحيات والأدوار المعرّفة ويضبط كل دور معرّف على ما يقوله الملف بالضبط
setting:listيسرد الإعدادات وقيمها (مدير المنصة)
setting:setيضبط أي إعداد (مدير المنصة)

engineering:about

$ php artisan engineering:about

بلا وسائط أو خيارات. يطبع إصدار الحزمة، والنمط المسجَّل (أو not installed (run php artisan engineering:install))، وفحصًا لـ PHP وLaravel مقابل blueprint.support.

  • مرفوض رمز الخروج 1 مع Environment is not compatible: upgrade the items marked ✗. (البيئة غير متوافقة: رقِّ العناصر المعلَّمة بـ ✗.)

engineering:install

$ php artisan engineering:install [--profile=PROFILE] [--force] [--allow-downgrade] [--permissions]
الخيارالمعنىالافتراضي
--profile=basic أو modular أو saas أو tenant-saasيُسأل عنه تفاعليًا. في الوضع غير التفاعلي: النمط المسجَّل، وإلا blueprint.default_profile، وإلا modular
--forceيستبدل ملف الإعدادات المنشور (ويُحفظ القديم باسم config/blueprint.php.bak)، ويسمح أيضًا بالانتقال إلى نمط أدنىمعطّل
--allow-downgradeيسمح بالانتقال إلى نمط بقدرات أقلمعطّل
--permissionsيهيّئ الأدوار والصلاحيات: ينشئ صنف التعريفات Permissions (وCentralPermissions في tenant-saas)، وترحيل spatie (وفي tenant-saas أيضًا في database/migrations/tenant)، ويضيف HasRoles إلى App\Models\User. يُرفض دون spatie/laravel-permission بالإصدار 8 أو أحدث، وفي وضع الفرق (teams) في spatie، وإعادة تشغيله آمنة. شغّل بعده php artisan migrate؛ وتطبيق tenant-saas فيه مستأجرون موجودون يشغّل أيضًا php artisan tenants:migrate وpermissions:sync وpermissions:sync --centralمعطّل

يسجّل النمط في config/blueprint.php (وينشره إن لم يكن موجودًا)، ويمسح الإعدادات المخزّنة مؤقتًا، وفي saas وtenant-saas يولّد تعريفات الميزات والإعدادات وترحيلاتها، وفي tenant-saas يجهّز stancl/tenancy أيضًا.

  • مرفوض Install aborted: environment is not compatible.
  • مرفوض Unknown profile "<value>". Choose one of: basic, modular, saas, tenant-saas.
  • مرفوض الانتقال إلى نمط أدنى في الوضع غير التفاعلي: Refusing to drop <capabilities>. Re-run with --allow-downgrade. وفي الوضع التفاعلي يسأل: This removes <capabilities> from the project. Continue? (الافتراضي: لا).
  • مرفوض Could not record the profile in config/blueprint.php.

make:crud

$ php artisan make:crud <module> <entity> [--fields=LIST] [--feature=KEY] [--api] [--web] [--permissions] [--owned]
الوسيط / الخيارالمعنىالافتراضي
moduleاسم الوحدة، مثل Ordersإلزامي
entityاسم الكيان بصيغة المفرد، مثل Orderإلزامي
--fields=قائمة name:type مفصولة بفواصل، مثل "name:string,quantity:int,note:?string"لا شيء، وعند إضافة جانب إلى CRUD موجود يُعاد استخدام الحقول الموجودة
--feature=مفتاح الميزة الذي يجب أن يكون مفعّلًا لهذه المسارات (saas، tenant-saas)، ويضيف الوسيط feature:<key>لا شيء (بلا بوابة)
--apiJSON APIمفعّل عند عدم تمرير --api ولا --web
--webصفحات Bladeمعطّل
--permissionsتفحص السياسة صلاحيات مسمّاة (<uri>.view و.create و.update و.delete)، وتُضاف المجموعة إلى Permissions::groups() (وإلى CentralPermissions للوحدة المركزية)، وتثبت الاختبارات القواعد. يحتاج إلى engineering:install --permissionsمعطّل
--ownedالسجلات ملك للمستخدم الذي أنشأها: عمود user_id يضبطه إجراء الإنشاء (لا من المدخلات أبدًا)، وقائمة محصورة بسجلات المستخدم، وصلاحية إضافية <uri>.any توسّع ما يملكه المستخدم من صلاحيات إلى كل السجلات. السجل الذي لا يستطيع المستخدم عرضه يعيد 404. يحتاج إلى --permissionsمعطّل

شغّله مرة أخرى بالجانب الآخر (--web بعد --api، أو العكس) لإضافته، ويُعاد استخدام النموذج والبيانات والإجراءات والسياسة المشتركة. أول تشغيل بـ --web ينشئ أيضًا التخطيط المحدد في blueprint.layout.

  • مرفوض Invalid entity name "<entity>". Use a singular name, e.g. Order.
  • مرفوض Entity names must be singular, e.g. <singular>.
  • مرفوض --feature needs the saas or tenant-saas profile.
  • مرفوض Unknown feature "<key>". Add it to <FeaturesClass> first.
  • مرفوض Features are per tenant; central module routes have no tenant. Drop --feature or use a tenant module.
  • مرفوض ليس في الوحدة routes/api.php أو routes/web.php للجانب المطلوب.
  • مرفوض spatie/laravel-permission <version> is not supported; permissions need ^8.0. أو spatie teams mode (permission.teams) is not supported.
  • تحذير The '<group>' group in <file> has no '<ability>'; another CRUD may use it. Add '<ability>' to '<group>' in <file>, then … (المجموعة معرّفة من قبل دون صلاحية يفحصها هذا الـCRUD)
  • مرفوض في tenant-saas، وحدة لا تستخدم مساراتها مجموعة tenant ولا central.
  • مرفوض كيان مفرده وجمعه متطابقان، مع --web.
  • مرفوض --fields doesn't match the existing <Entity> CRUD (<fields>). Leave --fields out to reuse them.
  • مرفوض ملف هدف موجود مسبقًا، أو اسم مسار مستخدم، أو كيان يتعارض مع صنف يستخدمه الكود المولّد، أو قالب ينتج كودًا غير صالح.
  • مرفوض إضافة جانب بقيمة --feature مختلفة عن مسارات الجانب الموجود.

الوسيط / الخيارالمعنىالافتراضي

  • مرفوض بدون النمط tenant-saas وstancl/tenancy، أو إذا لم يكن App\Providers\TenancyServiceProvider مسجَّلًا.
  • مرفوض Run tenant:create from the central app, not inside a tenant.
  • مرفوض Invalid tenant name "<name>". Use lowercase letters, numbers and dashes, e.g. acme.
  • مرفوض Invalid domain "<domain>": it must be a subdomain of <base>.
  • مرفوض Domain "<domain>" already belongs to tenant "<id>".
  • مرفوض Database "<db>" is the central database.
  • مرفوض Database "<db>" already exists. Pass --existing-database to use it for this tenant.

أوامر الميزات والإعدادات. الأوامر السبعة أدناه تحتاج إلى النمط saas أو tenant-saas. في saas تعمل على التطبيق ويُرفض --tenant، وفي tenant-saas يكون --tenant إلزاميًا (ما عدا features:sync). حالات الرفض المشتركة:

  • Features and settings need the saas or tenant-saas profile.
  • --tenant only applies to the tenant-saas profile.
  • --tenant is required in the tenant-saas profile.
  • Tenant "<id>" not found.

  • مرفوض spatie/laravel-permission <version> is not supported; permissions need ^8.0. أو spatie teams mode (permission.teams) is not supported.
  • رمز الخروج 1 no permission tables — run php artisan migrate (قاعدة بيانات واحدة، أو central: مع --central)، أو Tenant "<id>": no permission tables — run php artisan tenants:migrate (وتُزامَن بقية المستأجرين)
  • مرفوض --tenant and --central only apply to the tenant-saas profile.
  • مرفوض Tenant "<id>" not found.
