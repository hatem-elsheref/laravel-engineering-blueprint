الميزات والإعدادات

في النمطين saas وtenant-saas، تشغّل الميزات القدرات وتوقفها، وتحفظ الإعدادات قيمًا محددة الأنواع. وكلاهما معرَّف في الكود. في saas توجد مجموعة واحدة للتطبيق، وفي tenant-saas مجموعة لكل مستأجر، مخزّنة في قاعدة بياناته.

تعريف الميزات

engineering:install ينشئ app/Shared/Features/Features.php (مفتاح الإعداد blueprint.features). كل مفتاح ميزة وحالته الافتراضية موجودان هناك فقط:

final class Features
{
    public const ORDERS = 'orders';
    public const REPORTS = 'reports';

    public static function defaults(): array
    {
        return [
            self::ORDERS => true,
            self::REPORTS => false,
        ];
    }
}

تُخزَّن الحالة في جدول features (key، enabled). المستأجرون الجدد يحصلون على القيم الافتراضية من tenant:create. في saas، شغّل php artisan features:sync مرة واحدة بعد الترحيل. المفتاح الذي لا صف له يُعدّ معطّلًا.

فحص الميزات وحماية الكود بها

الواجهة Feature للقراءة فقط. المفتاح غير المعروف يرمي خطأ.

Feature::enabled(Features::REPORTS);
Feature::disabled(Features::REPORTS);
Feature::ensure(Features::REPORTS); // throws when disabled
Feature::all();                     // key => bool

إخفاء زر ليس حماية. افحص في الخلفية:

أينكيف
المساراتالوسيط feature:orders، أو feature:orders,reports (يجب أن تكون كل الميزات المذكورة مفعّلة). 403 عند التعطيل.
CRUD المولّدmake:crud Orders Order --feature=orders يضيف وسيط المسار واختبارًا له. راجع CRUD.
المهام (Jobs)new RequireFeature(Features::ORDERS) في دالة middleware() الخاصة بالمهمة (Best\Blueprint\Features\RequireFeature)
الإجراءات، والمتحكمات، والمهام المجدولةFeature::ensure(...)
التنقل، والعناصر المرئيةBlade @feature('orders') … @endfeature. للعرض فقط.

في tenant-saas، إذا لم يكن هناك مستأجر نشط، تُقرأ كل الميزات على أنها معطّلة.

أوامر الميزات

حالة الميزات لا تتغير إلا عبر الطرفية، وعلى يد مديري المنصة.

$ php artisan feature:list --tenant=acme
$ php artisan feature:enable reports --tenant=acme
$ php artisan feature:disable reports --tenant=acme
$ php artisan features:sync

feature:enable reports --tenant=acme

  • ملاحظة يكتب الصف reports في جدول features الخاص بالمستأجر acme بحالة مفعّل، داخل قاعدة بيانات ذلك المستأجر.
  • مرفوض بدون --tenant في tenant-saas، أو مع --tenant في saas، أو لمستأجر غير معروف، أو لمفتاح غير موجود في Features.

انظر أيضًا: feature:enable · feature:disable · feature:list · features:sync

features:sync يضيف المفاتيح المعرّفة التي لا صف لها بعد، بحالتها الافتراضية. لا يغيّر الصفوف الموجودة أبدًا. في tenant-saas يعمل على كل المستأجرين، أو على من تمرّرهم فقط: --tenant=acme --tenant=beta. يُفحص كل المستأجرين المذكورين قبل تغيير أي منهم.

تعريف الإعدادات

engineering:install ينشئ app/Shared/Settings/Settings.php (مفتاح الإعداد blueprint.settings):

self::APP_NAME => ['type' => 'string', 'default' => 'My App', 'editable_by' => 'tenant', 'ability' => 'manage-settings'],
self::APP_LANGUAGE => ['type' => 'string', 'default' => config('app.locale', 'en'), 'editable_by' => 'tenant', 'ability' => 'manage-settings'],
self::ORDERS_AUTO_CONFIRM => ['type' => 'bool', 'default' => false, 'editable_by' => 'platform'],
المفتاحالمعنى
typestring أو int أو float أو bool أو array
defaultالقيمة المُعادة عندما لا يكون هناك شيء مخزّن
editable_bytenant (يُغيَّر من كود التطبيق) أو platform (من الطرفية فقط)
abilityصلاحية Gate التي يحتاجها المستخدم لتغيير إعداد tenant، وهي إلزامية لهذه الإعدادات

لا يوجد صف في جدول settings إلا بعد ضبط قيمة. المستأجرون الجدد لا يحتاجون إلى صفوف إعدادات.

قراءة الإعدادات وكتابتها

Setting::get('app.language');        // typed value, or the default
Setting::set('app.language', 'ar');  // tenant settings only, through their Gate ability

Setting::set() يرفض إعدادات platform، والقيم ذات النوع الخاطئ، والمستخدمين الذين يرفضهم Gate. عرّف الصلاحية التي تستخدمها الإعدادات المولّدة، مثلًا في AppServiceProvider::boot():

// Example only: decide who may change tenant settings in your app.
Gate::define('manage-settings', fn (User $user) => $user->is_owner);

أوامر الإعدادات

$ php artisan setting:list --tenant=acme
$ php artisan setting:set orders.auto_confirm true --tenant=acme

setting:set orders.auto_confirm true --tenant=acme

يستطيع مديرو المنصة ضبط أي إعداد، tenant أو platform. تُقرأ القيمة بصيغة JSON (true، 5، ["a"]، "text")، وأي قيمة ليست JSON صالحًا تُؤخذ نصًا عاديًا. ضع -- قبل الأرقام السالبة.

  • مرفوض مفتاح غير معروف، أو قيمة من نوع خاطئ، أو غياب --tenant في tenant-saas، أو وجود --tenant في saas.

انظر أيضًا: setting:set · setting:list

من يستطيع الكتابة

الكتابةمسموحة من
حالة الميزاتأوامر الطرفية فقط (مديرو المنصة)
إعدادات platformأوامر الطرفية فقط
إعدادات tenantكود التطبيق عبر Setting::set() مع صلاحية Gate، أو الطرفية

أصناف الكتابة الإدارية التي تقف خلف الأوامر ترفض العمل أثناء معالجة طلب HTTP، بما في ذلك اختبارات HTTP في تطبيقك، وفي tenant-saas عندما لا يكون هناك مستأجر نشط. في اختبارات saas يبدأ جدول features فارغًا، فتكون كل الميزات معطّلة، لذا استدعِ app(\Best\Blueprint\Features\FeatureAdmin::class)->sync() أو ->enable('orders') في beforeEach.
