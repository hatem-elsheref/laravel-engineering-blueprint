Languages

The package translates the interface: generated Blade pages and the package's own messages. It does not translate your data; storing records in several languages is up to your app.

Configure languages

// config/blueprint.php
'locales' => ['en', 'ar'],                  // languages the app serves
'rtl_locales' => ['ar', 'fa', 'he', 'ur'],  // shown right-to-left

locales defaults to ['en']. The app's default language is Laravel's app.locale (APP_LOCALE), as configured when the app boots.

How a request's language is chosen

The SetLocale middleware is added to the web and api groups. Only languages in blueprint.locales are accepted; the first match wins.

OrderAPI requests (JSON or /api/*)Web requests
1Accept-Language header, by quality valueThe visitor's choice, stored in the session by /locale/{locale}
2The app.language setting (saas and tenant-saas; in tenant-saas only inside a tenant)
3The app default (app.locale)

The language is set on every request, so a long-running worker never keeps the previous request's language.

Language switcher

The package registers GET /locale/{locale}, named blueprint.locale, in the web group. It stores the language in the session and redirects back. A language not in blueprint.locales returns 404.

<a href="{{ route('blueprint.locale', 'ar') }}">العربية</a>

The generated layout shows these links on its own when more than one language is configured.

Right-to-left layout

The layout that make:crud --web creates (resources/views/layouts/blueprint.blade.php) sets <html lang dir> from the current language: dir="rtl" for languages in rtl_locales, ltr otherwise.

Error pages. Laravel's error pages (403, 404, …) show translated titles but use Laravel's own layout with <html lang="en">. For right-to-left error pages, run php artisan vendor:publish --tag=laravel-errors and set lang and dir in resources/views/errors/layout.blade.php the way the blueprint layout does.

Translating strings

  • Generated pages and package messages use __() with English keys.
  • The package ships lang/ar.json with Arabic for its own strings: buttons such as Save and Delete, status messages such as ":item created.", "This feature is not enabled.", and Laravel's "This action is unauthorized." and error page titles.
  • make:crud --web adds the entity and field names (for example "Order", "Orders", "Quantity") to lang/<locale>.json for every configured language other than en, with the English text as the value. Existing translations are kept. Translate the new values.
  • For Laravel's validation messages, run php artisan lang:publish and add lang/ar/validation.php.

Adding a language

  1. Add the code to blueprint.locales, for example ['en', 'ar', 'fr']. If it is written right-to-left and not already listed, add it to rtl_locales.
  2. Create lang/fr.json and translate your strings. Package strings without a translation show in English.
  3. Run make:crud --web as usual; new entities get their keys added to lang/fr.json. Entities generated before you added the language need their names added by hand.
  4. Optionally set the app.language setting per tenant with php artisan setting:set app.language fr (add --tenant=acme in tenant-saas).

For a new app, bin/new-app sets the languages for you. The first one becomes the default (APP_LOCALE):

$ bin/new-app ~/Sites/shop --profile=saas --locales=en,ar
